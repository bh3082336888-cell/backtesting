# Phase 3b-2 Proposer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `lab propose`. It is an unattended loop with the following steps:
1. Claude Opus 5.5 proposes strategy plugins, through `claude -p` and with no tools.
2. Each plugin is judged against the unchanged bar.
3. A per-idea record is kept, which the human reads on a new dashboard page.

The plan also covers the harness changes the loop needs.

**Architecture:** The plan has two parts.
- **Part A (Tasks 1–14)** changes the harness: the judge, the benchmarks, the store, and a new `lab preflight`. Each change is its own commit with its tests.
- **Part B (Tasks 15–27)** adds `perp_lab/proposer/`. This is trusted orchestrator code that does four things:
  - builds a prompt from whitelisted verdict fields;
  - calls `claude -p` as a subprocess;
  - checks the reply in code;
  - runs `lab preflight` and `lab judge --proposer` as subprocesses.

  The model reads nothing and runs nothing.

**Tech Stack:**
- Python ≥ 3.11, pandas, numpy, SQLAlchemy Core (SQLite), typer, Streamlit and pytest.
- The Claude Code CLI (`claude`, 2.1.306 on this machine) is the only model access.

**Spec:** `docs/superpowers/specs/2026-10-19-proposer-design.md`, approved 2026-10-21 (1f188a6). Read it alongside this plan; section names below are the spec's.

**Branch and commands:**
- **Branch:** create `feat/proposer` from `spec/proposer` in the main checkout `/home/burhan/backtesting`. Sandbox tests fail from a second worktree, because the editable install points at the main checkout.
- **Tests:** run them with `.venv/bin/pytest -q`; there is no `python` on PATH. The suite (about 650 tests, real sandbox included) must pass after every task.

## Global Constraints

- **The model.** It is `claude-opus-5-5`, pinned by full ID, with `model_training_cutoff: 2026-06-30`. The cutoff must be before `holdout_start` (2026-07-01). An alias such as `opus` refuses to start.
- **Model access.** The model is reached only through `claude -p` on the user's login. There is no API key, no SDK and no new pip dependency.
- **Imports.** `perp_lab/proposer/` never imports `perp_lab.judge`, `perp_lab.holdout`, `perp_lab.store` or `perp_lab.data`. It may import `perp_lab.dsr`, `perp_lab.config` and `perp_lab.plugins`.
- **Subprocesses.** The proposer starts only these, all through `perp_lab/proposer/proc.py`:
  - `lab judge NAME --tf TF --proposer`;
  - `lab preflight FILE --tf TF`;
  - `claude`;
  - `git rev-parse` and `git status`.
- **What the model never sees.** Nothing sent to it (argv or stdin) carries any of these:
  - the time of a judge run, an exam or a file;
  - a run id or a report path;
  - anything from `lab.db`, the holdout log or `data/`;
  - anything from `runs/` other than verdict contents;
  - `lab judge` stdout or stderr.
- **Writes.** The proposer writes only under `proposer.state_dir` (`proposer/`) and new files in `strategies/`. It never overwrites or deletes a file in `strategies/`.
- **Verdicts.** A verdict file never carries a number derived from holdout data.
- **Config defaults** (spec, Config):
  - `timeframes: [15m, 1h, 4h]`;
  - `trials_per_day: 12`;
  - `trials_total: 100`;
  - `proposals_per_idea: 4`;
  - `fixups_per_proposal: 3`;
  - `max_grid_combos: 16`;
  - `overlap_max: 0.5`;
  - `corr_max: 0.8`;
  - `max_input_tokens_per_day: 4000000`;
  - `max_output_tokens_per_day: 500000`;
  - `effort: high`;
  - `state_dir: proposer`.
- **Tests.** No test uses the network or the real `claude`, except the one fixture capture in Task 22. Orchestrator tests put a fake `claude` first on PATH.
- **Commits.** One concern per commit, with its tests in the same commit (org rule). Each commit message ends with the session's Co-Authored-By and Claude-Session lines.
- **Style.** Match the surrounding code: module docstrings that say why, `from __future__ import annotations`, and comments only where the reason isn't obvious.

## Review Focus

1. **Verdicts from before schema 2** (no `diagnostics`, 50/50 random entry). The piles must not guess: such a verdict's pile is `unknown` until `lab verdict-refresh` runs, and `lab propose` refuses to start while a seeded verdict lacks diagnostics. Tests: Tasks 18 and 25.
2. **Model source that mentions `PARENT` only in a comment or a string**, or that has a BOM or CRLF line endings. Only an assignment to `PARENT` is refused, and the written plugin is UTF-8 with LF endings and no BOM. Test: Task 19.
3. **A plugin that never holds a position** on the synthetic market or OOS. Its overlap is 0.0, never NaN or a ZeroDivisionError, and a correlation over fewer than 30 shared days is `None`. Test: Task 8.
4. **A `claude` stream with a non-JSON line**, or that ends before `init` or without a `result`. This is a `ModelCallError`, which is retried: never a success, never a crash. Test: Task 22.
5. **A plugin left in `strategies/` by a crashed session with other bytes.** The copy is refused, nothing is overwritten, and the proposal is recorded `broken` / `name_taken`. Test: Task 23.

### Task 3: Transient sandbox failures (#15)

The retry rule, which the spec leaves to this plan:
- The kinds `died`, `timeout` and `cpu_limit` can be caused by the machine. When one survives the client's own retry on a judgement's 1st or 2nd attempt (`trial_attempts` < 3), nothing is recorded but the trial. `lab judge` then exits 1 with a message.
- The same failure on the 3rd attempt is recorded as a plugin-error kill, as today.
- Every other kind (`exception`, `protocol`, `mismatch`, `metadata`, `features`) is the plugin's fault and is recorded at once.

**Files:** Modify `perp_lab/sandbox/errors.py`, `perp_lab/judge/judge.py`, `perp_lab/cli.py`, `README.md` (Plugin sandbox section). Test: `tests/test_judge.py`.

**Interfaces:**
- Produces:
  - `errors.TRANSIENT_KINDS = ("died", "timeout", "cpu_limit")`;
  - `judge.TRANSIENT_MAX_ATTEMPTS = 3`;
  - `class judge.TransientFailure(RuntimeError)` with `.kind: str`.
- **CLI:** `lab judge` catches `TransientFailure` and prints `transient sandbox failure (<kind>); the trial is registered; run lab judge on the same file again`, then exits 1.
- Consumes: `db.trial_attempts` (Task 2).

### Task 8: Positions, overlap and correlation in `perp_lab/overlap.py`

**Files:** Create `perp_lab/overlap.py`. Test: `tests/test_overlap.py`.

**Interfaces:**
- **`H_MS = 3_600_000`.**
- **`positions(trades: pd.DataFrame) -> pd.Series`.** The index is a MultiIndex (symbol: str, hour: int64); the value is the side (+1 or −1, int8).
  - A trade holds hours `floor(entry_time/H_MS)` through `floor((exit_time − 1)/H_MS)`, so a position counts for every hour it was held during any part of.
  - When one plugin holds both sides in one (symbol, hour), the later trade's side wins.
  - It needs the columns `symbol`, `entry_time`, `exit_time` (ms) and `side`.
- **`overlap(a: pd.Series, b: pd.Series) -> float`:** |(symbol, hour) held on the same side by both| ÷ |(symbol, hour) held by either|. It is 0.0 when neither holds anything.
- **`mirror_overlap(a, b) -> float`:** the same with the sides opposite.
- **`return_corr(a: pd.Series, b: pd.Series, min_days: int = 30) -> float | None`:** the Pearson correlation of daily returns on their shared days. It is `None` with fewer than `min_days` shared days.
- **`nearest(pos, daily, others: dict[tuple[str, str], tuple[pd.Series, pd.Series | None]], k: int = 3) -> dict`:**
  - it returns `{"position": [...], "mirror": [...], "correlation": [...]}`;
  - each entry is `{"strategy", "timeframe", "value"}`, rounded to 3 decimals;
  - each list is sorted descending, and correlation by |value| (signed in the output);
  - entries whose value is 0 or `None` are left out.

### Task 22: The `claude -p` caller

**Files:** Create `perp_lab/proposer/model.py`, `tests/fake_claude.py` and `tests/fixtures/claude_stream_ok.jsonl`. Test: `tests/test_model.py`.

**Interfaces:**
- **`Reply`**, a dataclass: `proposal: dict`, `usage: dict`, `cost_usd: float | None`.
- **Errors:**
  - `class ModelConfigError(Exception)`: the session stops with `model_config`;
  - `class UsageLimit(Exception)` with `.resets_at: datetime | None`;
  - `class ModelCallError(Exception)`: retryable.
- **`argv(pc, system: str, schema: dict) -> list[str]`**, exactly: `[pc.claude_bin, "-p", "--model", pc.model, "--effort", pc.effort, "--tools", "", "--strict-mcp-config", "--safe-mode", "--disable-slash-commands", "--no-session-persistence", "--permission-prompts", "none", "--system-prompt", system, "--json-schema", json.dumps(schema), "--output-format", "stream-json", "--verbose", "--include-hook-events"]`.
- **`env() -> dict[str, str]`:** `{"HOME": os.environ["HOME"], "PATH": os.environ["PATH"]}`.
- **`call(pc, system: str, user: str, schema: dict, transcript: Path) -> Reply`:**
  - the working directory is `tempfile.mkdtemp(prefix="perp-lab-proposer-")`, removed afterwards;
  - `user` goes in on stdin;
  - stdout is read line by line, and every line is appended to `transcript` as is;
  - the process is killed after `pc.call_timeout_s`.
- **The rules on the stream:**
  - **First line not JSON, or not `type == "system"` with `subtype == "init"`** → `ModelCallError`.
  - **The init message fails its check** → kill the process, `ModelConfigError`. The check:
    - its model equals `pc.model`;
    - its tools are exactly `["StructuredOutput"]`;
    - `mcp_servers`, `skills` and `slash_commands` are empty, where present.
  - **A later message whose `type` or `subtype` contains `hook`** → kill, `ModelConfigError`.
  - **A `rate_limit_event` whose status isn't `"allowed"`** → `UsageLimit(resets_at)`.
  - **Then:**
    - a non-JSON line, EOF before `result`, a non-zero exit or a timeout → `ModelCallError`;
    - a `result` with `is_error`, or without `structured_output` → `ModelCallError`;
    - otherwise → a `Reply` built from `structured_output`, `usage` and `total_cost_usd`.
- **`call_with_retries(pc, system, user, schema, transcript, *, sleep=time.sleep) -> Reply`:** 5 tries on `ModelCallError`, with backoff of 30, 60, 120 and 240 s. `UsageLimit` and `ModelConfigError` pass straight through.
- **`cli_version(pc) -> str`:** `claude --version`.
- **`probe(pc, transcript) -> None`:** one call with schema `{"ok": boolean}` and stdin `Reply with ok true.`.
- **`tests/fake_claude.py`** is an executable that `tests/test_model.py` copies, as `claude`, into a temporary directory put first on PATH:

### Task 23: The loop

**Files:** Create `perp_lab/proposer/loop.py` and `perp_lab/proposer/digest.py`. Test: `tests/test_loop.py`, `tests/test_digest.py`.

**Interfaces:**
- Consumes everything from Tasks 15–22.

  - **`header(model, cutoff, cli_version, commit, branch)`.** It adds a warning line when the branch isn't `main`.
  - **`line(seq, plugin, tf, kind, idea_title, outcome)`.** It is written and flushed as each proposal happens.
  - **`pause(reason, until)`.**
  - **`finish(counts_by_pile, new_progress_ideas, stop_reason, tokens_in, tokens_out)`.**
- **`Deps`**, a dataclass of injectable callables:
  - `call_model(system, user, schema, transcript) -> Reply`;
  - `preflight(path: Path, tf: str) -> tuple[int, dict]`;
  - `judge(name: str, tf: str, log: Path) -> int`;
  - `now() -> datetime`, `sleep(seconds: float)`;
  - `pin_check()`.

  `default_deps(cfg, pc, repo)` wires the real ones:
  - `judge` is `proc.run(lab_argv("judge", name, "--tf", tf, "--proposer"), stdout=log, stderr=STDOUT, start_new_session=True)`, waited on;
  - `preflight` parses the JSON on stdout.
- **`run_session(cfg, pc, *, days: float | None = None, trials: int | None = None, deps: Deps | None = None) -> str`** returns the stop reason, one of:
  - `trials_total`, `days`, `trials`;
  - `infra_errors`, `stuck`;
  - `model_call`, `model_config`;
  - `harness_changed`;
  - `signal`;
  - `budget_spent`.
- **Before the first round:**
  - take the session lock, a non-blocking flock on `<state_dir>/session.lock`; if it's held → `StartRefused`;
  - `settings.load`;
  - `pin.take`;
  - `model.cli_version` and `model.probe`;
  - seed the record if it is empty (Task 25);
  - re-judge any proposal in state `copied`, which is crash recovery;
  - the snapshot: re-read every proposal's verdict file at `<judge.verdicts_dir>/<plugin>@<tf>@<hash[:10]>.json`;
  - refuse to start if `trials_used() ≥ trials_total`, or if any verdict has `holdout_reason == "budget_spent"`.
- **Each round** follows the spec's One round, steps 2–10:
  - **Fix-ups.** Every fix-up is a fresh call with `prompt.fixup(...)`, up to `fixups_per_proposal` per proposal, shared by the contract, idea-rule, assembly and preflight checks. After that the proposal is `dropped`.
  - **Before preflight and judge**, `deps.pin_check()` runs.
  - **The judge.** If the UTC day changed since preflight, preflight runs again. Then the judge.
  - **The copy.** If `strategies/<name>.py` exists with other bytes, the proposal is recorded `broken` / `name_taken` (Review Focus 5), and nothing is overwritten.
  - **After a verdict:**
    - the pile;
    - the after-trial duplicate check (the spec's After-trial overlap, using `pc.overlap_max`, `pc.corr_max` and the exemptions);
    - the idea's `family` (`verdict["lineage_id"]`), `root_plugin` and status;
    - a digest line.
- **Quotas, checked before each round:**
  - `judge_calls_on(today) ≥ trials_per_day`, or token usage today ≥ either cap → sleep until the next 00:00 UTC, and note it in the digest;
  - `trials_used() ≥ trials_total` → stop `trials_total`;
  - the `--trials` count reached → stop `trials`;
  - `--days` elapsed → stop `days`.
- **Stops:**
  - **3 consecutive** judge exits of 1 or preflight exits of 1 → `infra_errors`;
  - **5 consecutive** dropped proposals → `stuck`;
  - **errors:**
    - `ModelCallError` after retries → `model_call`;
    - `ModelConfigError` → `model_config`;
    - `PinError` → `harness_changed`;
  - **a verdict showing `budget_spent`** → `budget_spent`.
- **Usage limit:** `UsageLimit` sleeps until `resets_at`, or 3,600 s without one, then repeats the same call. The digest notes the pause.
- **Signals.** SIGINT and SIGTERM handlers are installed for the session.
  - **The first** sets a flag: the running judge finishes, then the session stops with `signal`.
  - **The second** kills the judge's process group and records the proposal `broken` / `interrupted`, with `judged_at` set so that it counts toward the quota.
